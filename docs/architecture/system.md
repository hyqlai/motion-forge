# 系统架构

## 1. 最终产品

Motion Forge 是“Agent Skill + 本地制作内核 + 动效卡库 + 浏览器工作台 + 独立视频工程”，不是单一脚本或固定模板。用户给出链接、音频、主题或素材后，系统先提交制作方案，再制作有声样板镜，两道确认完成后自动完成全片。

## 2. 主链

```text
独立工程生成（forge create）
  → 输入适配与素材本地化
  → brief.json / assets.json / analysis/
  → 内容与视觉导演
  → film.json
  → 目标 Film 校验、卡片选择、布局和局部时间线
  → Remotion 合成与渲染
  → 内容、画面、声音、同步验收
  → MP4 + 自包含工程 + 项目工作台
```

链接、纯音乐、歌曲、主题和混合素材只在输入适配器与主时钟选择上不同，后续共用同一条制作链。真实项目由 `forge create` 在模板目录之外生成，持有 `core/`、`cards/`、`scenes/`、`providers/`、`scripts/`、`workbench/`、`examples/`、锁文件、配置和素材的完整副本；生成后不再引用模板/技能目录。

## 3. 模块边界

### core

拥有 Film IR、Zod 校验、时间线编译、卡片注册接口、场景渲染器和制作状态机。core 不知道具体项目文案，也不 import 某张业务分镜的内部组件。

### cards

每张卡是独立包，包含 `card.json`、实现、预览和说明。卡片只依赖稳定的 Motion Core API。新增、修改或删除卡片不应要求修改时间线编译器。

### scenes

每镜独立包含实现、props 和 spec。分镜使用局部帧号，不写全片绝对帧号；分镜之间禁止 import 内部组件。共享能力只能来自 core 或明确的共享图形库。

### transitions

转场属于两个分镜的边界，单独实现和注册。修改转场不重写前后分镜。转场的时间锚由核心时间线统一换算。

### providers

链接抓取、免费图片/视频/UI/音频检索、TTS、ASR 和可选 AI 生成都通过 provider 接口接入。初始化把用户本地素材真实复制到项目 `public/assets/<id>/`，Film IR 和 assets.json 只登记 `public/` 下的相对路径；渲染不依赖远程 URL、外部绝对路径或软链接。

### workbench

直接读取同一份 Film IR、卡片清单和场景组件，不维护第二份时间线。支持全片与单镜预览、参数调整、换卡、本地导出和 Film IR 写回；写回会校验目标 Film 并在设计变化时重置 G1/G2 状态。复杂画面仍可回到独立分镜代码修改。

## 4. 渲染技术路线

Remotion 统一负责帧时钟、图层、音视频和输出。

- HTML/CSS：排版、UI 和网页复刻。
- SVG：矢量图形、路径、遮罩、图表和形变。
- Canvas 2D：粒子、纹理和大量程序绘制。
- Three.js：模型、材质、灯光、空间运镜和 Shader。

所有动画只由当前帧计算，禁止自运行 `requestAnimationFrame` 时间线、无种子随机和依赖渲染顺序的隐藏状态。Three.js 使用 Remotion 官方桥接；Chromium OpenGL 默认使用 ANGLE，渲染命令允许用 `--browser-executable` 和 `--gl` 覆盖以便诊断本机 WebGL 环境。

## 5. 两道确认闸

### G1 分镜与视觉设计

确认每镜叙事目的、实际上屏文字、素材、风格元素、布局、主动效、运镜、转场和时间锚。未确认不能进入正式实现。

### G2 有声样板镜

用真实素材和最终技术路线制作代表镜。确认后进入批量生产。实现若偏离已确认的文字、布局、主动效或运镜，应重新确认受影响镜头。

状态机固定为：

```text
design-review → sample-review → production → delivered
```

工作台或其他设计修改使已审批内容发生变化时，项目退回 `design-review`，旧 G1/G2 结论失效，必须重新确认。

## 6. 独立修改与增量渲染

- 分镜只使用局部帧；全片帧号由 core 编译。
- 文案、素材、布局和主题通过 props 注入。
- 单镜可独立注册 Composition、预览和渲染。
- 修改单镜只需重渲该镜及受影响的边界转场和音频。
- 内容哈希用于缓存；不能用缓存掩盖依赖变化。
- 全局主题与单镜覆盖分开，避免换皮需要修改每张卡。

## 7. 主时钟优先级

用户硬约束优先，其后按实际内容选择：口播字级时间 → 歌曲乐句/歌词 → 纯音乐节拍/段落 → 生成旁白 → 阅读时长。同一分镜只指定一个主时钟，其他锚点引用它，不混用多套绝对时间。

## 8. 全局与片种规则

全局只检查内容保真、确定性、越界、意外停死、音画同步、音频健康和可复现渲染。持续微动、禁止裸切、必须一镜到底、必须卡拍等要求属于片种或风格策略，不作为全局硬规则。
