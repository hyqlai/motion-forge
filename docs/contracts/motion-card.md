# 动效卡协议

## 1. 分层

- 运动原语：缓动、弹簧、路径、形变、遮罩和相机投影等纯函数。
- 动效卡：可独立装配的运动能力。
- 布局/风格包：栅格、安全区、字体、颜色和材质。
- 叙事结构包：片种段落和能量曲线。

四者不得混成一个不可拆分的大模板。

## 2. 分类与场景

卡片按作用对象分为 `component`、`text`、`camera`、`media`、`transition`、`environment`。另用语义索引描述钩子、定义、例证、列举、步骤、对比、数据、转折、金句、章节和结尾等使用意图。

每张卡必须回答：

- 适合什么片种和叙事时刻？
- 需要什么素材和画幅？
- 典型时长和能量档是什么？
- 解决什么叙事问题？
- 哪些情况不要用？
- 可与哪些卡搭配，和哪些卡冲突？

## 3. 独立包

```text
cards/<kind>/<slug>/
  card.json
  index.tsx
  preview.tsx
  README.md
```

`card.json` 包含稳定 ID、版本、分类、语义、输入槽、开放 props、固定命门、时间模型、画幅能力、渲染技术、使用场景、冲突、预览和 QA 信息。

## 4. 解耦要求

- 内容、素材、主题、尺寸和时长通过 props 或上下文注入。
- 运镜卡包装外部内容，不内置具体业务页面。
- 转场卡接收前后场景，不拥有业务内容。
- 动画分为固定动作段与可伸缩 hold；不得通过整体加速破坏手感。
- 只使用局部帧和固定种子，任意 seek 可复现。
- 卡片不得 import 其他业务分镜或复制其他卡的内部实现。
- 卡片只依赖 core 的稳定 API，新增卡不修改时间线编译器。

## 5. 单一实现生成预览

实现组件同时服务 Gallery、工作台和成片。预览配置生成 GIF/MP4、六帧图、参数面板和索引，不维护另一份手写 HTML 动画作为视觉真相。

## 6. 验收

每卡至少检查：Manifest Schema、独立渲染、首帧/动作峰值/落定帧、文字和主体边界、横竖屏或明确限制、可伸缩 hold、固定种子、props 默认值和使用场景完整性。迁移卡还需与原参考预览对照，保留运动特征，不要求保留原示例文案。
